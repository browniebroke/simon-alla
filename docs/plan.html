2. Architecture

Publishing and visiting are two separate paths. When Simon publishes, the site is rebuilt. Visitors only ever load files that have already been built.

Repository layout

One repo managed with npm workspaces (no extra tooling, since npm comes with Node), with two packages:

  • web/ is the Astro site, built and deployed by Cloudflare Pages from Git. Pages builds from the repo root with npm run build:web and serves web/dist.
  • studio/ is Sanity Studio: the schemas plus the French locale (@sanity/locale-fr-fr). You deploy it with sanity deploy.

The two are connected with the @sanity/astro integration and @sanity/image-url, which builds image URLs.

5. Sanity content model

There are seven document types. Three are singletons, meaning there's exactly one of each, such as the site settings. Simon never sees "schema" or "slug": every field has a French label and a one-line hint.

TypeKindFields
siteSettings (Paramètres)SingletonName, tagline, phone, email, area served (text + list of towns), logo, default share image, SEO description
homePage (Accueil)SingletonHero title, subtitle, hero background, round hero photo, intro text (rich text), featured services, featured projects, call-to-action text
service (Service)CollectionTitle, slug, order, short summary, cover image, description (rich text), photo gallery
project (Réalisation)CollectionTitle, slug, date, town, service (reference), cover image, gallery, optional before and after photos, description
contactPage (Contact)SingletonIntro text, email that receives form messages, confirmation message
page (Page simple)CollectionTitle, slug, body. Used for Mentions légales and Confidentialité.
testimonial (Avis client)Collection, optional, laterQuote, first name and town, date
  • Images: every image field has hotspot cropping turned on and requires alt text (written as "Description de la photo"), which helps accessibility and SEO.
  • Rich text: limited to bold, italic, links and lists. Without heading levels or colours, Simon can't break the design.
  • Studio menu: customised so the singletons show as fixed entries ("Accueil", "Paramètres") rather than lists.
  • Seed content: the flyer text, so the site isn't empty on day one.

6. Contact form and email

  • Fields: nom, téléphone, email, commune, type de projet (one of the services), message, and optional photos (deferred, see below).
  • Where it posts: /api/contact, the only route marked prerender = false. It runs as a Cloudflare Pages Function.
  • Server checks: it verifies the Turnstile token, validates the fields, rejects submissions that fill a hidden honeypot field, then sends the email to the address set in contactPage. Reply-To is set to the visitor's address.
  • Data storage: nothing is stored on our side. That keeps the privacy page short.
  • Without JavaScript: the form still posts normally and redirects to a "Merci" page. With JavaScript it shows the result inline.
  • Photo uploads: deferred to v1.1. They're useful ("send me a photo of your wall"), but add size limits and storage. In v1 the site points people to email instead.

Cloudflare Email Service needs the sending domain verified with SPF, DKIM and DMARC records. If it's not available on the account yet, use Resend's free plan with the same DNS records.

7. Hosting, domain and publishing

  1. The GitHub repo is connected to Cloudflare Pages, which builds web/ on every push to main and creates preview builds for branches.
  2. A Pages deploy hook is called by a Sanity webhook whenever a document is published.
  3. Simon hits "Publier" and the site is live about 1–2 minutes later. The Studio tells him so in a hint under the publish button.
  4. The domain is registered at OVH or Gandi, with its nameservers moved to Cloudflare. The www address redirects to the bare domain.
  5. Environment variables are set in Pages: the Sanity project ID and dataset, the Turnstile secret, and the email API key or binding.

Alternative: Cloudflare now recommends Workers with static assets for new projects. Moving later is easy, because the Astro adapter supports both. Pages is the pick for now because it has built-in deploy hooks.

Backups: a monthly GitHub Action runs sanity dataset export and stores the export as a release asset. That covers the case where Sanity loses the data or you want to leave.

8. SEO, legal and accessibility

Local SEO

  • Page titles: written for local searches, e.g. "Taille de pierre et aménagement paysager à [ville] — Simon Alla".
  • Structured data: a LocalBusiness JSON-LD block (name, phone, area served, opening hours), filled from siteSettings.
  • Discovery files: sitemap.xml (via @astrojs/sitemap), robots.txt, a canonical URL on every page, and Open Graph images for sharing on WhatsApp and Facebook.
  • Google Business Profile: outside the website, but worth more for local search than anything on the site. Link it to the site.

Legal (France)

  • Mentions légales are required for a professional site under the LCEN law. They include Simon's name or business name, legal status, SIRET, address (or registered address), contact details, the publication director, and the host (Cloudflare's company details).
  • Confidentialité: what the form collects, why, how long it's kept (only in Simon's inbox) and the contact for GDPR requests.
  • No cookie banner: not needed, because there's no tracking. Turnstile is a security measure and the analytics use no cookies.
  • Image rights: check the licences of the photos on the flyer. They may be stock images.

Accessibility and performance

  • Contrast: meets WCAG AA (see the note on yellow), with visible keyboard focus and real <label>s on the form.
  • Images: sized with srcset from the Sanity CDN and lazy-loaded below the fold. Target: Lighthouse 95+ on mobile.

9. Build phases

  1. Set up. Create the repo (npm workspaces, already done) and the Sanity project and dataset. Scaffold web/ and studio/. Write the schemas, French locale and Studio menu, and deploy the Studio.
  2. Design. Set up the colour and font tokens and the components (wave dividers, ringed photo, blob, header, footer, service card, project card). Build the home page with hard-coded flyer content and check it matches the flyer.
  3. Connect content. Wire Astro to Sanity with GROQ queries and build every page in the site map. Enter the seed content.
  4. Contact form. Build the endpoint, Turnstile, email sending and the "Merci" page.
  5. Deploy. Set up Cloudflare Pages, the domain and DNS, the email DNS records, the Sanity webhook and deploy hook, and the backup Action.
  6. SEO and legal. Add the JSON-LD, sitemap and Open Graph images, write the legal pages, and run a Lighthouse and accessibility pass.
  7. Handover. Invite Simon to Sanity and write a one-page guide in French ("Ajouter une réalisation", "Changer une photo"). Spend 30 minutes walking him through it.
